# AstrBot TTS Enhancer

> **Пусть ответы AstrBot звучат с естественными эмоциями, диалектами и персонализированным голосом —**
> устраняя разрыв между «простым текстовым вводом» и богатыми возможностями современных TTS-провайдеров благодаря высокомодульной архитектуре для подключения любого сервиса синтеза речи.

## Зачем нужен TTS Enhancer?

AstrBot по умолчанию может передавать LLM только обычный текст. Но современные TTS-сервисы давно не ограничиваются «чтением текста» — они поддерживают громкость, интонацию и скорость, а также теги эмоций, многоязычность и диалекты, клонирование и дизайн голоса…

Традиционный способ вызова позволяет передать лишь один параметр `text`, из-за чего все эти возможности пропадают впустую. А многие провайдеры предоставляют только API без удобного веб-интерфейса для управления клонированными голосами и дизайном.

**TTS Enhancer создан именно для этого дисбаланса:**

- **Высокомодульная мульти-провайдерная архитектура** — каждый провайдер — независимый адаптер, который никак не влияет на остальные.
- **Механизм документов о возможностях (Capability Docs)** — к каждому провайдеру прилагается Markdown-документ с описанием поддерживаемых параметров и способов использования; SubAgent применяет его для интеллектуальной генерации оптимальных параметров.
- **Фронтенд по требованию** — переиспользуемые компоненты управления для провайдеров без веб-консоли; провайдеры с официальной консолью просто ссылаются на внешнюю ссылку, без дублирования реализации.

## Основной дизайн

### 1️⃣ Мульти-провайдерные адаптеры

Каждому TTS-провайдеру достаточно унаследовать `TTSProviderAdapter` (или готовую общую базу, например `BailianSpeechSynthesizerAdapter`) и реализовать:

- `get_tool_schema()` → определяет структуру параметров Function Calling
- `get_subagent_system_prompt()` → внедряет документ о возможностях в SubAgent
- `call_api()` → вызывает реальный API
- `create_voice() / list_voice() / delete_voice()` → управление голосами

Добавление провайдера — это один Python-файл плюс один Markdown-документ; плагин обнаруживает его автоматически.

### 2️⃣ Документы о возможностях

К каждому провайдеру прилагается документ `providers/docs/{template_key}.md`, описывающий:

- Какие параметры поддерживаются (`instruction`, `volume`, `rate`, `pitch`, `language_hints`…)
- Списки тегов эмоций, списки диалектов, примеры использования
- Диапазоны значений и значения по умолчанию

SubAgent **динамически читает этот документ** в момент синтеза и генерирует параметры, соответствующие возможностям провайдера, исходя из контекста диалога — никогда не выходя за допустимые границы.

### 3️⃣ Фронтенд: переиспользуемые компоненты + кастомизация по требованию

Плагин предоставляет **переиспользуемые фронтенд-компоненты** (`components/common/`), инкапсулирующие стандартные сценарии управления голосами:

- `bailian_speech_synthesizer.js` — режимы клонирования / дизайна (аудио клонирования кодируется в браузере как Data URL), превью, список, удаление
- `voice_preview_modal.js` — модальное окно превью голоса с прослушиванием / сохранением / удалением
- `delete_confirm_modal.js` — модальное окно подтверждения удаления (обходит блокировку `confirm()` в песочницах)

Также поддерживаются индивидуальные сценарии для каждого провайдера (например, трёхшаговый поток MiniMax «неактивный → превью → активация»).

Общая логика вынесена в `composables/`:

- `useAudioManager.js` — синглтон глобального воспроизведения аудио
- `useTextValidator.js` — проверка длины текста (CJK-символ = 2 единицы)
- `useClipboard.js` — работа с буфером обмена
- `useToast.js` — уведомления

Детали на уровне страницы:

- **Глобальная полоса громкости** — закреплённая вверху панель, остающаяся регулируемой при открытом модальном окне (меняйте громкость во время превью, не закрывая окно)
- **Анимации появления/исчезновения** — плавное появление страницы и вкладок, лёгкое всплывание модальных окон и toast; всё отключается при `prefers-reduced-motion`
- **Архитектура наложений** — оверлеи модальных окон и toast всегда телепортируются в `body` и позиционируются в `vw/vh`, что защищает их от побочных эффектов containing-block / стековой компоновки анимаций страницы

Для каждого провайдера:

- **Нужен UI** → переиспользуйте общие компоненты + тонкую кастомизацию; достаточно зарегистрировать и настроить `providerConfig` (список языков, ссылки справки и т.д.) в `app.js`.
- **Уже есть официальная консоль** → настройте только внешнюю ссылку; повторная реализация не требуется.
- **Есть особые сценарии взаимодействия** → напишите отдельный кастомный компонент (например, список аудио MiniMax, декодирование hex).

> Замысел дизайна: **закрыть пробел в управлении для провайдеров, у которых есть только API, но нет UI**, а не навязывать единообразие.

## Записи синтеза (необязательно)

Плагин сохраняет каждый результат TTS-синтеза (голос чата / превью голоса / прослушивание дизайна / отправка Agent'ом и т.д.) как «запись синтеза». В единой странице управления (`pages/tts_studio`) их можно воспроизводить, просматривать метаданные (источник / провайдер / время / текст / формат / длительность / размер / параметры улучшения) и удалять по отдельности либо очистить все разом.

- **Многоуровневое хранение (по соглашению AstrBot)**: метаданные (источник / провайдер / время / текст / формат / длительность / размер / параметры улучшения) идут в официальный KV (автоизоляция по namespace плагина, единый ключ `synthesis_index`); аудио-бинарники попадают в `plugin_data/synthesis_records/` и вне KV.
- **Политика хранения** задаётся параметром `synthesis_record_max`: `0` или отрицательное значение отключает сохранение; положительное целое число оставляет только N последних записей, удаляя самые старые (и их аудиофайлы) при превышении. Безлимитное хранение **не** поддерживается (чтобы диск не заполнялся бесконечно).

## Извлечение долговременной памяти (LivingMemory, необязательно)

Если в той же экземпляре AstrBot установлен и включён плагин LivingMemory, а также настроена модель векторного эмбеддинга, TTS Enhancer может перед синтезом извлекать связанную долговременную память и внедрять её в SubAgent как ориентир для оценки стиля речи (например, устойчивые предпочтения пользователя по голосу или контекст беседы), придавая голосу ощущение «памяти».

- `memory_retrieval_top_k`: количество извлекаемых воспоминаний; `0` = отключено (по умолчанию).
- `memory_retrieval_query_strategy`: источник поискового запроса. `user_message` использует текст для синтеза; `prefix` использует фиксированный префикс (чтобы не подмешивать в поиск не относящийся к чтению текст и не подтягивать шум).
- `memory_retrieval_prefix`: фиксированный префикс поиска, показывается и применяется только при стратегии `prefix`.
- Полная деградация без сбоев: когда LivingMemory отключён, отсутствует Embedding Provider или вызов завершился ошибкой, извлечение тихо пропускается без влияния на TTS-синтез.

## Быстрый старт

1. **Установите плагин** — найдите и установите в маркетплейсе плагинов AstrBot.
2. **Настройте провайдера** — конфигурация плагина → добавьте хотя бы одного провайдера.
3. **Заставьте модель выводить тег `<tts>`** — основная модель оборачивает `<tts>текст для синтеза</tts>` в ответе; плагин автоматически обрабатывает это и отправляет голосовое сообщение.
4. **Используйте Tool** — плагин регистрирует инструмент `send_voice_to_user`, позволяя модели самостоятельно решать, когда отправить голос, без тегов.

## Конфигурация (сокращённо)

```yaml
enable_enhance: true              # Включить авто-улучшение через SubAgent
enhance_llm_provider: ""          # Модель для улучшения (можно дешёвую/бесплатную)
context_window: 10                # Окно контекста (в обменах)
dual_output: false                # Выводить и текст, и голос
# ---- Извлечение долговременной памяти (LivingMemory, необязательно) ----
memory_retrieval_top_k: 0         # Количество извлекаемых записей (0 = отключено)
memory_retrieval_query_strategy: "user_message"  # Источник запроса: user_message / prefix
memory_retrieval_prefix: "Предпочтения голоса пользователя"  # Фиксированный префикс (только для стратегии prefix)
page_background: []               # Фоновое изображение страницы управления (тип file; пусто = скрыто)
page_background_opacity: 0.5       # Прозрачность фона (0~1; применяется только при заданном изображении)
page_background_blur: 0            # Размытие фона (0~30px; применяется только при заданном изображении)
synthesis_record_max: 50           # Макс. число хранимых записей (0 или отриц. = отключено; положит. целое = хранить N последних; безлимит не поддерживается)
providers:                        # Список провайдеров (несколько, с откатом)
  - __template_key: bailian_qwen_audio_3_0_tts
    display_name: "Мой голос"
    priority: 0
    persona_id: ""                # Привязка к персоне (необязательно; пусто = универсальный голос по умолчанию)
    api_key: "sk-..."
    workspace_id: "ws-..."
    model: "flash"
    voice: "longanhuan_v3.6"
    timeout: 60
```

Полный список параметров конфигурации — в справке на странице настроек плагина.

## Участие в разработке

Добавить нового TTS-провайдера просто:

1. **Напишите адаптер**: создайте `<vendor>_<model>.py` в `providers/`, унаследовав `TTSProviderAdapter` или готовую общую базу.
2. **Напишите документ возможностей**: создайте `providers/docs/<template_key>.md` с подробным описанием параметров, тегов и примеров.
3. **Фронтенд (по требованию)**:
   - Нужен UI: создайте Vue-компонент в `pages/tts_studio/components/`, переиспользуйте `components/common/` и настройте `providerConfig`; зарегистрируйте сопоставление в `app.js`.
   - Есть официальная консоль: просто настройте внешнюю ссылку в `app.js`.
   - Есть особые сценарии (например, поток MiniMax «неактивный → превью → активация»): напишите отдельный кастомный компонент.
4. **Добавьте шаблон конфигурации**: расширьте `_conf_schema.json` пунктами провайдера.

Все новые провайдеры автоматически обнаруживаются и загружаются фабрикой — изменения ядра не требуются.
